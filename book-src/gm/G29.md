# Foundry Use, Editorial Notes and Sources

## What this edition changes

The original Cold Storage package supplied the Rainline setting, the 2274/2384 interval, eight pregens, forty historical sleeves, twenty recurring contacts, 160 relationship links, six factions, four adversary profiles and a seven-scene outline. This edition expands that structure into a complete run-ready book and introduces the three embodied AI rulers as the deeper conspiracy. The original historical contact identities remain intact.

The supplied Altered Carbon v1.1.2 system is treated as a dependency, not rewritten or bundled into this release. The new material does not claim official setting status. Fray, the high-risk recall costs and the final objective procedure are original adventure house rules, separately identified from the supplied system's Ego, resleeving and skill mechanics.

## Safe installation and updating

Back up the world first. Keep the module ID and folder name **cold-storage**. For a fresh world, use the module's full import to create the original actors, relationships, scenes and this book, then select six pregens and assign ownership. For an existing world, use **Import / Update Book Only**. That path updates journals and creates any missing new social NPCs; it does not reset PC statistics, resources, ownership, sleeve items, inventory or relationship states.

The book updater identifies its entries with source IDs, resolves cross-links after creation, and keeps original pages as GM-only recovery copies on the first migration when their content differs. Later source updates preserve an edited page as a GM-only recovery copy before replacement. Add your continuing campaign notes as separate pages or journals. Do not treat a source-managed page as the only copy of irreplaceable notes.

## Navigation and disclosure

Open the Book Console from the module's settings menus. It provides the running guide, chapter links, evidence handouts, Heat and Renewal counters, and manual Fray controls for active pregens. Fray changes are recorded only when the GM uses those controls; the module does not automatically apply Ego loss, roll continuity checks or adjudicate fracture consent. Use the actor sheet for core-system rolls and resources.

Player primers are public. The adventure, NPC dossiers, personal echo cards, recovery copies and unacquired evidence handouts begin GM-only. Reveal only a named handout, never an entire GM chapter. Personal cards should be granted only to the relevant player; the book console supports explicit recipients. A handout may be safe after discovery while still containing a late-game answer, so "handout" does not mean "public at import."

Document ownership protects normal journal visibility, not the secrecy of files in an installed module's publicly served assets. A player deliberately opening module source JSON could read published adventure text. Do not claim cryptographic secrecy. The design prevents accidental in-app disclosure and keeps ordinary player navigation separate.

## Existing scenes and art

The original eight scene placeholders and project branding are retained. They are presentation backdrops, not newly commissioned battlemaps. The book uses zones, conversations and objective encounters and is playable without tactical maps. No new audio, portrait pack or paid assets are included. The new three Benefactor actors are social reference NPCs, not elaborate automated boss sheets.

Scene journal links are assigned only when an original module scene exists and has no journal link already, so custom scene references are not silently overwritten. Existing scene art, walls, tokens and lighting are left alone by the book-only update.

## Local package versus hosted release

The supplied install ZIP is a local package. Its module manifest intentionally does not assert that a new hosted download already exists. The full source bundle includes a separate release-manifest template and publication instructions for the repository named in the original bundle. Uploading files to a repository or attaching a GitHub release remains a separate action; no account was changed while producing this edition.

For local Foundry, the extracted module folder belongs at Data/modules/cold-storage with module.json directly inside it. For Forge or a manifest-based deployment, use the documented repository/release workflow and verify the actual published manifest and archive before installing. The unchanged system must already be installed and enabled in the world.

## Validation boundaries

The package's automated checks inspect JSON, source IDs, linked journal targets, original content counts, permission defaults, schedule totals, evidence redundancy, JavaScript syntax and mocked import/update behaviour. They do not run a licensed Foundry server or your Forge world. The live checklist in docs/live-qa.md is therefore still required before a paid session, particularly for module activation, system rolls, player permissions and any platform-specific file upload workflow.
